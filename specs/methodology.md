# specs 方法论框架

一句话：约束"怎么写 spec"的五件思维工具，每篇规范从来源到验收都过一遍；
候选共 10 词、取 5，淘汰记录与证据边界在文末。

## 前言：权威关系

- 行为准绳是 tcode（`typescript/`），参照物是 zai-org/ZCode。与 tcode 行为冲突的 spec 是坏 spec；
  借鉴 ZCode 借的是不变量，不是权威——它的规模、产品形态、实现选型都不构成跟随理由。
  这条就是候选词"保持独立思考"在本框架中的落点。
- 分工：`specs/README.md` 管"写什么、怎么验收"（主题边界 + 冒烟全绿），本文件管"用什么思维工具写"。

## 流水线

蒸馏（来源）→ 第一性原理（不变量）→ 高内聚低耦合（边界）→ 奥卡姆剃刀（规模闸门）→ 对抗式审查（验收）

## 五件工具

### 1. 蒸馏 Distillation

- 定义：从庞杂的具体实现里提炼语言中立的最小规则集；spec 是蒸馏物，不是实现说明书。
- ZCode 映射：约 34.6MB TS、7458 文件的 monorepo，可借鉴的只有不变量——如"会话是事件流，
  UI 与持久化都是事件的投影"（`contracts/src/events/session.events.ts` + `event-reducer.ts`）。
- 应用动作：动笔先问"这条规则去掉实现细节后还剩什么"；产出必须是语言中立规则 + 五版落点指针，
  禁止照抄某一家实现的内部结构。自检标准：换一门语言读这篇 spec 仍然成立。

### 2. 第一性原理 First Principles

- 定义：每篇从本质约束出发，再对照 tcode 与 ZCode 的解法检验是否同构；不为复刻某个实现写 spec。
- ZCode 映射：plan mode 被建模为权限策略（`permission/plan-mode-policy.ts`，ExitPlanMode 仅 plan 态可用），
  本质约束是"模式 = 一组规则"，实现形式自由。
- 应用动作：spec 第一栏写"本质约束"；tcode 与 ZCode 解法不同构时写明差异，并判定哪边才是本质——
  判 tcode 非本质的偏离必须五版同步修改，不允许规范与现实各说各话。

### 3. 高内聚低耦合 High Cohesion, Low Coupling

- 定义：主题单一职责，边界显式，依赖方向单向且写进规范。
- ZCode 映射：六边形架构——contracts 纯契约包（`*.port.ts`）定义端口、内核零 I/O、adapters 负责装配。
  本仓已有同构纪律：kernel 不 import core、`turn.py` 是唯一事件生产者。
- 应用动作：spec 标注"输入/输出边界 + 禁止的依赖方向"；借鉴 ZCode 模式前先指出它减少的是哪一种耦合，
  说不出就不借。

### 4. 奥卡姆剃刀 Occam's Razor

- 定义：借不变量不借规模；在满足本质约束的方案里取最简。
- ZCode 映射：一体两面——7458 文件的 monorepo 对阵纯标准库五语言家族（rust 仅 serde_json+ureq）。
  它的 vm cell 沙箱、SQLite journal、插件市场形态不构成借鉴义务。
- 应用动作：每条借鉴写明"最少实现落五版"的做法；超出本仓现有能力线的机制不进 spec，
  记入路线图（`docs/从零到一到一百.md`）的搁置/不做清单并留触发条件。

### 5. 对抗式审查 Adversarial Review

- 定义：spec 写完只算一半，主动构造违反它的反例才算验收。
- ZCode 映射：`turn-state.ts` 的 canTransitionTo 守卫非法迁移、`permission/broker.ts` 默认拒绝
  （无客户端即拒绝）——机制本身就为对抗性输入而设。
- 应用动作：spec 附"反例清单"（非法状态迁移、超预算、断流、审批无客户端、五版行为差异逐条列）；
  变更后五版冒烟必须全绿（specs/README.md 写作约定 2）。

## 建议栏目（工具的落地形态）

每篇 spec 固定六栏：**本质约束**（←第一性原理）、**语言中立规则**（←蒸馏）、
**边界与依赖方向**（←高内聚低耦合）、**五版落点**、**反例清单**（←对抗式审查）、
**低置信区**（←"列出不自信的点"的残段，见淘汰记录）。
奥卡姆剃刀是全程闸门，不设栏目。
