# 学习指南：用 Python 标准库手写一个 coding agent

> 面向"会用 Python，但没手写过 agent"的读者。所有路径与行号都是本仓库的真实位置，
> 可直接打开对照。行号对应版本 v0.1.0，代码改动后以函数名为准定位。

## 1. 一句话定义

**用标准库手写 coding agent = 一个 while 循环 + 一个函数清单 + 一组本地命令的包装。**
循环把对话历史发给 LLM 的 HTTP 接口，模型如果要求"调工具"，就从清单里找到对应
Python 函数执行，把结果拼回历史再发——直到模型不再要工具。没有魔法，没有框架，
`urllib.request` 发请求、`json` 拼协议、`subprocess` 跑命令，全部是你在标准库文档里
见过的东西。本仓库 `pcode/core/agent_loop.py:33` 的 `run_turn` 就是这个循环本体，
不到 90 行；`pcode/plugins/` 下每个工具就是一个函数加一份 JSON Schema。

## 2. 三个核心要素（配生活类比）

| 要素 | 类比 | 一句话 | 代码位置 |
| --- | --- | --- | --- |
| agent loop | 服务员下单后厨返工 | 你（用户）点单，服务员（循环）递给后厨（模型）；后厨说"先帮我切个葱"（工具调用），服务员切好递回去，后厨才出最后的菜。菜没上之前，这个传菜-返工循环一直转，但最多转 40 圈防止后厨打转（`pcode/core/agent_loop.py:19` 的 `MAX_TOOL_ROUNDS`） | `pcode/core/agent_loop.py:33` |
| SSE 流式 | 水龙头逐杯接，而非等满壶 | 模型的回答是一滴水一滴水流出来的；流式就是端着杯子在水龙头下接，接到一杯就端给用户看一眼。`data:` 行是"滴答"的节拍，`[DONE]` 是关阀门的信号 | `pcode/providers/sse.py:8` 的 `sse_data` |
| 插件注册表 | 墙上的插座面板 | 每个能力（工具/命令/协议/壳）是一个插头，注册表是插座面板：插上就能用，拔掉就消失，面板本身不懂任何电器。加能力=做一个插头+在面板上留一个插孔（清单加一行），核心电路（agent loop）零改动 | `pcode/kernel/registry.py:12`、清单 `pcode/plugins/__init__.py:26` |

## 3. 最常见的误解

**误解："调 LLM API 必须装 requests/httpx，否则发不了 HTTP 请求。"**

不对。发 HTTP 请求、读流式响应，`urllib.request`（标准库）就够：

- 发 POST 并逐块读流式响应：`pcode/providers/openai.py:50`，就一行
  `urllib.request.urlopen(request, timeout=300)`，返回的响应对象本身可迭代（逐行）；
- SSE 解析不需要任何库：SSE 只是"以空行分隔的文本块"，`pcode/providers/sse.py:8`
  用 30 行手写解析（找 `data:` 前缀、按空行切事件）；
- 第三方 HTTP 库解决的是连接池、异步、重试策略这类**规模化**问题——单用户本地工具
  一个同步请求接一个响应，用不上。

本项目零第三方依赖（`pyproject.toml` 没有任何 dependencies），五场景端到端冒烟
（`test/smoke.py`）全靠标准库跑通，就是反证。

## 4. 本仓库真实代码怎么读（按一条命令的生命周期）

在 REPL 敲一句话按回车之后发生的事，按顺序：

| 步骤 | 发生了什么 | 位置 |
| --- | --- | --- |
| 1. 读入 | `input('pcode❯ ')` 拿到一行 | `pcode/shell/repl.py:70` |
| 2. 裁剪 | 估算 token（`字符数/3` 上取整+每条 8），超 10 万就从最旧的工具输出裁起，最近 12 条不动 | `pcode/core/trim.py:23`（估算）、`pcode/core/trim.py:34`（裁剪） |
| 3. 入列与落盘 | 用户消息追加进 `app.messages`，此后每条新消息追加写进 `~/.pcode/sessions/*.jsonl` | `pcode/core/turn.py:26` 的 `run_user_turn` |
| 4. 发请求 | 把全部历史 POST 给模型端点，流式读回；429/5xx/网络错误在**首字节前**最多重试 3 次（退避 1s/2s） | `pcode/providers/openai.py:50`、退避 `pcode/providers/retry.py:35` |
| 5. 工具调用 | 模型回 `tool_calls` 就逐个执行：查清单 → 查权限 → `run(args)` → 结果以 `role='tool'` 消息回填历史，回到第 4 步 | `pcode/core/agent_loop.py:33` |
| 6. 权限闸门 | 写类工具（write/edit/bash/web_fetch）先调 `check`：非 yolo 就打印预览问 `[y/n/a]`，答 `a` 置 yolo 后续全放行 | `pcode/core/permission.py:27`、UI 适配 `pcode/shell/repl.py:33` |
| 7. 断尾修复 | 若中途异常/中止，给"有调用无回应"的工具补占位消息，保证会话文件对 API 始终合法 | `pcode/core/turn.py:66` |
| 8. 会话恢复 | `/resume` 读旧 JSONL 换新文件继续写；标签取首条用户输入前 60 字符 | `pcode/core/session.py:34` |

两处值得精读的"协议翻译"：工具调用参数是流式分片到达的，OpenAI 按 index 分槽拼
arguments 碎片（`pcode/providers/openai.py:88`）；Anthropic 的 `input_json_delta`
同理（`pcode/providers/anthropic.py:168`），且消息形状要整体翻译（system 提顶层、
tool 消息转 user 角色的 tool_result 块、相邻同角色合并，`pcode/providers/anthropic.py:33`）。

一处值得精读的"安全边界"：SSRF 三道闸——只许 http/https、字面 IP/保留域名直接拒绝、
DNS 解析后逐地址复检，重定向每跳全部重来（`pcode/plugins/tools/netguard.py:34`、
`pcode/plugins/tools/netguard.py:120`、循环 `pcode/plugins/tools/web_fetch.py:62`）。
判定表全部是可单测的纯函数（`test/test_netguard.py`）。

## 5. 行业对比：LangChain 等工业框架 vs 手写

| 维度 | 工业框架（LangChain/LlamaIndex 等） | 手写（本仓库路线） |
| --- | --- | --- |
| 上手速度 | 快：几行代码跑通 demo | 慢：SSE/协议/循环都要自己写 |
| 黑盒程度 | 高：抽象层层叠叠，出问题要读框架源码 | 零：每个字节从哪来都知道 |
| 定制边界 | 框架留的扩展点之内 | 无边界，改循环本体也只是一改普通函数 |
| 依赖风险 | 传递依赖树 + 破坏性版本变更 | 零依赖，Python 升级即全部升级 |
| 面试价值 | 会用 API | 能讲清 agent loop、流式协议、SSRF 防线的每个细节 |
| 适合场景 | 快速拼装 RAG/多链路原型、团队统一技术栈 | 学习原理、做小而硬的本地工具、需要审计每一行安全的场景 |

结论不是"框架不好"，而是**顺序**：先手写一个最小版理解本质（就是本文），再上框架
才分得清哪些是本质、哪些是框架的包装。真要工业化（多用户、并发、观测、评测），
再引入框架或自建平台也不迟。

## 6. 从读完到掌握的下一步路径

1. **加一个工具**（最小改动，体验插件模型）：照 `pcode/plugins/tools/todo.py` 的样子
   写一个新 dataclass + `run` 函数，在 `pcode/plugins/__init__.py:26` 的清单挂一行。
   建议：`patch`（多段 hunk 编辑）、`notebook`（读写 Jupyter 单元格）。
2. **加一个协议**：照 `pcode/providers/anthropic.py` 实现 `chat()`，注意复用
   `pcode/providers/sse.py` 与 `pcode/providers/retry.py`，清单里放在 openai（恒真兜底）之前。
   建议：Gemini 的 OpenAI 兼容层适配或 Ollama 本地协议。
3. **加一个壳**：照 `pcode/shell/repl.py` 实现 `start(app)`。建议顺序：单发模式
   （`pcode -q "问题"`）→ web 壳（`http.server` + SSE，注意绑 127.0.0.1 + token 校验，
   可参考 tcode 的 `src/shell/web.ts`）。
4. **补硬能力**（每项都是一个真正的工程课题）：
   - 上下文：从"裁工具输出"升级为"历史摘要压缩"（改 `pcode/core/trim.py`）；
   - 并发：无依赖的工具调用并行执行（`threading`，注意只读工具才可并行）；
   - 沙箱：bash 工具加白名单/工作目录隔离（改 `pcode/plugins/tools/bash.py` 的守卫）；
   - 子 agent：让模型能调用"另一个 agent loop"作为工具（在 `run_turn` 之上包一层）。
5. **验收自查**：跑 `python -m unittest discover -s test -v` 与 `python test/smoke.py`；
   再照 tcode README 的验收节，用真实模型端点让 pcode 无人值守修一个带 bug 的玩具项目——
   这是"可用"与"演示"的分界线。
