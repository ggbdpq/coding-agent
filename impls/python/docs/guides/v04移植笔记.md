# v0.4 移植笔记：tcode R4/R5 与第一批 v0.4 能力落进 pcode

结论先行：本次把 tcode（v0.5.0 仓库）中属于 v0.3→v0.4 范围的 R4/R5 与三项 v0.4 能力移植到 pcode，
共改 16 个文件、新建 6 个文件；单测 25→42 全绿，冒烟 5→6 场景全过。
Plan Mode / apply_patch / Skill 索引 / diff 预览属 tcode v0.5 范围，明确未移植。

## 一、移植了什么

## 二、Python 惯用表达与 tcode 的差异点

| 点 | tcode（TS） | pcode（Python） | 说明 |
|---|---|---|---|
| usage 回调载荷 | `onUsage?: (usage: {prompt_tokens; completion_tokens}) => void` | `on_usage: Callable[[int, int], None]`（两个位置参数） | 标准库不引 dataclass 当回调参数，turn 层再包成 `Usage` 事件 |
| 事件判别联合 | 对象字面量 + `type` 字段 | dataclass + `ClassVar[str] type`，`match/case` 解构渲染 | 新增 `Compact(saved_tokens)` 事件变体 |
| compact 切片 | `messages.splice(1, tailStart - 1, summaryMsg)` | `messages[1:tail_start] = [summary_msg]` | 切片赋值天然等价 splice 的"替换+插入" |
| 白名单路径判定 | `target === root \|\| target.startsWith(root + path.sep)` | `target == root or target.is_relative_to(root)`（`pathlib.Path.resolve` 两侧归一化） | 3.9+ 标准方法，免手拼分隔符 |
| @引用正则 | `/(^|\s)@([^\s@]+)/g` + `replace(fn)` | `re.compile(r'(^|\s)@([^\s@]+)')` + `re.sub(fn)` | sub 天然全量替换，无需 g 标志 |
| 封顶读文件 | main.ts 与 repl.ts 各写一份 `cappedRead` | 收敛为 `core/atrefs.py:capped_read` 一份，REPL 与 exec 共用 | 消重复；`open('rb').read(1MB)` 替代 fd+Buffer |
| CLI 解析 | 手写循环剥 `--approval` 的值 | `argparse`（`shell`/`task` 位置参数 + `--continue` 显式 `dest='resume_latest'`） | continue 是关键字，dest 必须显式 |
| exec 失败判定 | turn 异常路径也发 `turn_end(aborted/error)`，emit 里标 failed | 同步模型异常路径不发 turn_end，failed 由 exec 的 `except` 分支兜住 | 沿用 pcode v0.3 的已知差异（见 test_events.py 模块注释） |
| yolo 等价 | 启动时 `yolo \|\| config.approval === 'never'` | 同式写在 `__main__.py`；另因 /approval 可运行时改策略，命令内同步 `app.yolo.value` 让策略立即生效 | tcode 的 approval 只在装配时消费一次 |

## 三、踩坑记录

1. **OpenAI usage 块的 choices 为空**。`include_usage` 的 usage 随流末尾一个 `choices` 为空的 chunk 到达，
   pcode 旧代码 `if not choices: continue` 会先把它跳过。usage 解析必须放在 continue 之前
   （`pcode/providers/openai.py` 的 `_attempt`）。tcode 的代码顺序已暗示这一点，照抄旧 pcode 顺序就丢 usage。
2. **行为升级打破旧断言**。`test/test_compact.py` 首测曾断言压缩后 `len == 2`；保留 4 条尾部后是 6。
   tcode 上游同样改了这条断言（`test/compact.test.ts` 现断言 6 条 + 尾部相等），照做同步更新，
   "既有 25 测试保持全绿"即除这条随行为升级的断言外全部原样通过。
3. **`_read_json_config` 原来只保留 str 值**，`allowWriteDirs`（list）会被静默丢掉。改为返回原始
   `dict[str, Any]`，字符串取值统一走 `_file_str` 做类型守卫。
4. **dataclass 字段序**。`ToolPlugin` 插入带默认值的 `skip_permission` 必须放在无默认字段之后；
   全部既有调用方都用关键字传参，不受影响。
5. **直接给 App 塞 `store=object()` 会在 `start_session` 炸**——自验 /approval 命令时要给真 `SessionStore`。
6. **argparse 的 `--continue`**：`dest` 不能自动推导（continue 是保留字），显式 `dest='resume_latest'`。
7. **`PCODE_APPROVAL=never` 的等价性靠装配**：`yolo=args.yolo or config.approval == 'never'`，
   与 tcode 同式；只改 config 不读它的话策略是死的。
