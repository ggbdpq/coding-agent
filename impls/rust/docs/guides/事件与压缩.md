# 事件与压缩（R1 + R3 移植笔记）

> 前置阅读：[学习指南.md](学习指南.md)。所有路径都指本仓库真实文件，
> 参照实现是 `../typescript/`（Node 版，行为规格以此为准）。

## 一句话定义

**R1（事件模型）**：一轮对话发生的每件事（模型吐字、调工具、裁上下文、收尾）不再是散落的
回调，而是 `turn` 统一发出的带类型事件流；**R3（compact）**：上下文超预算时先请同一个模型
把旧对话压成一条任务摘要再继续，压不动才退回"裁旧丢历史"的 trim——**一个管"怎么记"，一个管
"记不住时先找重点"**。

## 三个核心要素（配生活类比）

| 要素 | 在哪里 | 类比 | 一句话 |
| --- | --- | --- | --- |
| `AgentEvent` | `src/kernel/types.rs` 的 `AgentEvent` | 电台统一频道 | turn 是唯一播音员，壳/测试/将来的审计都是听众——频道变乐器（加变体），听众不用换收音机 |
| `emit: &mut dyn FnMut(AgentEvent)` | `src/core/turn.rs` 的 `run_user_turn` 签名 | 一根直播话筒 | 话筒只有一支、沿调用栈往下传：轮前治理、循环内增量、收尾，全从同一支话筒出去 |
| `compact_context` | `src/core/compact.rs` | 会议纪要 | 20 页会议记录请人浓缩成一页纪要（保留目标/结论/待办），原文先不丢——纪要写砸了就当没发生 |

## 点破最常见误解

**误解："Rust 没有 TS 那种对象判别联合，做事件模型肯定很别扭。"**

恰恰相反。`{ type: 'tool_call', call_id, ... }` 这种 TS 判别联合在 Rust 里就是
`enum AgentEvent { ToolCall { call_id: String, ... }, ... }`——enum 变体自带载荷，
`match` 强制穷尽所有变体，漏处理一个编译器直接报错；TS 要靠 `switch (e.type)` 加
类型收窄人肉保证。五实现（ccode/gcode/pcode/tcode/rcode）对照里这是最贴切的一次移植。
证据：`src/kernel/types.rs` 的 `AgentEvent` 九个变体一屏放下，
`src/core/turn.rs` tests 里的 `event_type` 用一个 match 就完成全事件分发。

**误解二："把回调从散钩子改成事件流，得引入事件总线/观察者模式一堆抽象。"**

不需要。tcode 的做法就是给 `run_user_turn` 加一个 `emit` 参数，rcode 照搬：
`src/core/turn.rs` 里 turn 自己在四个时点直接调 `emit(...)`，循环内三个增量
（text/tool_call/tool_result）经 `RefCell` 共享同一支出入口。没有 trait、没有注册、
没有总线——事件模型的第一性是"谁生产、谁消费说清楚"，不是设计模式。

**误解三："compact 会把历史改了，风险很大吧？"**

风险被一条纪律锁死：**摘要失败时原 messages 原封不动，compact 永不破坏会话**。
实现上是"先算后改"：先拿全文去要摘要，拿到非空正文才 `truncate(1)` + push 摘要消息
（`src/core/compact.rs`）。对应单测 `摘要失败_原历史原封不动` 用快照逐条比对
（`src/core/compact.rs` tests）。

## 结合本仓库举例（建议阅读顺序）

1. **先看事件类型**：`src/kernel/types.rs` 的 `TurnEndReason` + `AgentEvent`。
   注意 `Aborted` 变体有注释说"同步模型无此路径"——保留它是对齐 tcode 的事件契约
   （见下文 Ctrl+C 一节）。
2. **再看生产者**：`src/core/turn.rs` 的 `run_user_turn`——发射顺序
   `trimmed（若有）→ turn_start → user → 循环内 text_delta/tool_call/tool_result → turn_end`，
   与 `../impls/typescript/src/core/turn.ts` 逐行同构。轮前治理也在这：估算超限先 `compact_context`，
   失败退 `trim_context` 并发 `Trimmed` 事件。
3. **然后看循环怎么把增量交出来**：`src/core/agentloop.rs` 的 `TurnDeps`——
   工具回调带 `call_id`（`on_tool_call: &dyn Fn(&str, &str, &Value)`），
   事件载荷由 turn 组装，loop 自己不知道 `AgentEvent` 的存在。
4. **再看消费者**：`src/shell/repl.rs` 的 `render` 闭包——match 四种事件各打印一行，
   其余 `_ => {}` 忽略。壳从"拼输出"变成了"订阅渲染"，行为与旧版逐字符一致。
5. **最后看压缩**：`src/core/compact.rs` 的 `compact_context`——≤5 条拒绝；
   transcript 取 `messages[1:]`；摘要消息固定格式
   `[此前对话的摘要——当前任务以此为背景继续]…[摘要结束]`；saved_tokens 与 trim 同式
   （`src/core/trim.rs` 的 `estimate_tokens`：`ceil(字符/3) + 8/条`，tool_calls 参数计入）。
   命令入口在 `src/plugins/commands/compact.rs`：失败只打印"压缩未执行：…"，绝不上抛。

## 与其他语言对照（本节重点：stdlib Rust 为什么连 Ctrl+C 都拦不了）

**"Rust 标准库没有信号处理器"是本次移植绕不开的硬约束。** tcode 的 R2（轮中真取消）
靠 `AbortController` + `AbortSignal`：流式中 Ctrl+C 中止本轮、保留上下文继续下一轮。
rcode 做不到，原因与代价如下：

| 环节 | tcode（Node） | rcode（Rust stdlib） |
| --- | --- | --- |
| Ctrl+C 拦截 | `process.on('SIGINT')` 内建 | stdlib 无信号 API，需 `ctrlc`/`signal-hook` crate——违反两依赖政策，不引 |
| 请求中止 | `AbortController` 传 `AbortSignal`，底层 fetch 随时掐断 | 无对应物；`ChatOptions.timeout`（20s）是唯一的"取消"兜底 |
| 轮中取消语义 | `TurnEndReason::Aborted` 有真实生产者 | `Aborted` 变体保留但无生产者；Ctrl+C 直接默认退出进程，轮中任务随进程消亡，无悬空资源 |
| compact 中止 | signal 已 abort → 抛 AbortError，原状 | 靠 20s 超时与错误路径，失败原状（单测锁定） |

这个取舍的账是这样的：

- **收益**：依赖清单停在 `serde_json + ureq` 两个（`Cargo.toml`），整条工具链
  （SSE 解析、重试、权限、会话）保持"手写即懂"；Ctrl+C 默认退出对单用户 CLI 是可接受行为，
  会话逐行落盘（`src/core/session.rs`）保证退出不丢历史。
- **代价**：R2 语义缺失（README"已知局限"明示）；超时是钝刀——模型卡住时用户最多等 20s
  （摘要请求）而不是随时掐断。
- **如果将来要补**：引 `ctrlc` 一个 crate、在 `src/shell/repl.rs` 装处理器、
  给 `ChatOptions` 加中止旗标（`Rc<Cell<bool>>` 轮询即可，同步模型不需要 async）。
  变体 `TurnEndReason::Aborted` 已经等在那里。
