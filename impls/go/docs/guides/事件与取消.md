# 学习指南：事件与取消

前置：读过 [学习指南.md](学习指南.md) 的 agent loop 主线。本篇覆盖 v0.3 移植的三个升级：
事件模型（R1）、可取消性（R2）、compact 摘要压缩（R3），重点是前两个——它们是同一个故事的
两面：**turn 把"发生了什么"说成事件，context 让"不想继续了"传遍全链**。

## 1. 一句话定义

turn（`internal/core/turn.go` 的 `RunUserTurn`）是唯一的事件生产者，把一轮对话的每个动作
发成规范 `AgentEvent`；壳只是消费事件做渲染的 switch。取消则是一条 context 链：REPL 用
`signal.NotifyContext` 把 Ctrl+C 变成 ctx 取消，HTTP 请求、SSE 读循环、bash 进程树全部
挂在同一条 ctx 上，谁收到取消谁自行收尾。

## 2. 要素类比

| 要素 | 生活类比 | 本仓库落点 |
| --- | --- | --- |
| `AgentEvent` 扁平 struct | 电台节目单：`Type` 是栏目名，其余字段是各栏目的内容；听众（壳/审计/测试）只听自己的栏目 | `internal/kernel/types.go`，10 个 `Ev*` 常量列出全部栏目 |
| `TurnEndReason` | 快递终态：completed=签收 / aborted=寄件人撤回 / error=运输破损 | `internal/kernel/types.go`，只在 `turn_end` 事件里出现 |
| `context.Context` | 电路总闸的拉闸令：REPL 每轮开始发一张令牌（ctx），HTTP 请求、SSE 流、bash 子进程全串在这张令牌上，令牌一作废全线停工 | `internal/shell/repl.go` 的 `signal.NotifyContext(...)` 生成，`core.RunUserTurn(ctx,...)` 逐层下传 |
| `signal.NotifyContext` | 把"按了 Ctrl+C"翻译成"令牌作废"的转换器；翻译完第一次就自动下班 | `internal/shell/repl.go`；第二次 Ctrl+C 落回系统默认行为=进程终止 |
| `errors.Is(err, context.Canceled)` | 查拉闸原因：错误链里有" canceled "记号就是人为中止（aborted），否则是真故障（error） | `internal/core/turn.go` 的 reason 判定、`internal/providers/retry.go` 的不重试判定 |
| `Emit` 回调字段 | 电台的播音管道：一个函数字段就是事件流，不需要 channel——turn 和壳在同一个 goroutine 里同步收听 | `internal/core/turn.go` 的 `TurnHooks.Emit`，`internal/shell/repl.go` 的 `renderEvent` |
| compact | 会议纪要：把 21 页逐字记录浓缩成 1 页纪要换进档案袋，原稿核实无误后才替换；浓缩失败就原样退回 | `internal/core/compact.go`，失败/取消时 `app.Messages` 原封不动 |

## 3. 最常见误解，逐个点破

| 误解 | 事实 | 本仓库证据 |
| --- | --- | --- |
| "context 必须贯穿一切函数签名才叫 Go 风格取消" | ctx 只需要到达**会阻塞的 I/O 边界**（HTTP、子进程、流读取）；纯内存函数挂 ctx 是纯税 | `TrimContext`/`EstimateTokens`（`internal/core/trim.go`）、`renderEvent`（`internal/shell/repl.go`）都没有 ctx；`Chat`/`Run`/`CompactContext` 这些会等外界的才有 |
| "第二次 Ctrl+C 强退要自己写信号计数器" | `signal.NotifyContext` 收到首个信号即取消 ctx 并自动注销监听；第二次信号回落到操作系统默认行为=直接杀进程。gcode 只是为了打一行提示才多挂了一层监听器 | `internal/shell/repl.go` 主循环里的 turnDone goroutine：首个 Done 后再 `NotifyContext` 一次，第二个信号来了先提示再 `os.Exit(130)` |
| "事件流需要 channel 或事件总线框架" | 生产者与消费者在同一调用栈上时，一个 `func(AgentEvent)` 字段就是事件流；channel 是为跨 goroutine 传递才存在的 | `TurnHooks.Emit func(kernel.AgentEvent)`；测试里收集断言只需 `eventCollector.emit`（`internal/core/turn_test.go`） |
| "Go 没有判别联合，表达不了规范事件" | 扁平 struct + `Type` 字符串判别 + 每个事件只读自己字段的注释约定；消费端 `switch` 的 `default` 分支忽略未知事件，天然前向兼容 | `internal/kernel/types.go` 的 `AgentEvent` 注释块列出每种类型各自的字段；`renderEvent` 的 `default` 直接跳过 turn_start/user/turn_end |
| "取消 = 一切立刻蒸发" | ctx 取消是**协作式**的：HTTP 靠 transport 断流、bash 靠 `CommandContext`+taskkill 杀树、工具里可能只体现为一条错误文本回流。turn 还要发 `turn_end(aborted)`、修复断尾、落盘，然后才把错误交回壳 | `internal/plugins/tools/bash.go` 的 `killTree` 与 `exit=cancelled` 文案；`internal/core/turn.go` 错误路径的断尾修复与事件顺序 |
| "压缩历史会破坏 assistant↔tool 配对" | compact 的产物是 `[system, 纯文本 user 摘要]`——没有 tool_calls 就没有配对边界问题；而且只在摘要**成功拿到非空文本**后才动历史 | `internal/core/compact.go` 的 `app.Messages = append(app.Messages[:1], ...)` 在错误检查之后 |

## 4. 在本仓库里对照读（建议顺序）

| 步骤 | 文件 : 函数 | 看什么 |
| --- | --- | --- |
| 1 | `internal/kernel/types.go` : `AgentEvent`/`TurnEndReason` | 事件契约本体：10 个类型、每个类型的字段归属注释 |
| 2 | `internal/core/turn.go` : `RunUserTurn` | 唯一生产者：治理(compact→trim) → turn_start{uuid} → user → 循环事件 → turn_end{reason}；错误路径先修断尾再落盘再发终态 |
| 3 | `internal/core/agentloop.go` : `TurnDeps` | 事件源头接线：`OnToolCall(callID, name, args)` 带模型的调用 id |
| 4 | `internal/shell/repl.go` : `renderEvent` | 最小消费者：text_delta 直写、tool_call/tool_result/trimmed/compact 各一行 |
| 5 | `internal/shell/repl.go` : 主循环 | 取消的起点：每轮 `signal.NotifyContext` + 二次强退 watcher + `errors.Is(err, context.Canceled)` 区分中止与出错 |
| 6 | `internal/providers/retry.go` : `WithRetry` | 取消纪律：`ctx.Err()` 前置检查 + 取消错误绝不重试 |
| 7 | `internal/providers/sse.go` : `SSEData` | 流式读取的取消：每次产出前检查 ctx，配合 `openai.go`/`anthropic.go` 流中 `ctx.Err()` 即弃半截消息 |
| 8 | `internal/plugins/tools/bash.go` : `runBash` | 子进程的取消：`exec.CommandContext` 只杀直系，`killTree` 补 taskkill /T /F 连坐，输出标注 `exit=cancelled` |
| 9 | `internal/plugins/tools/webfetch.go` : `runWebFetch` | 多跳请求的取消：每跳 `http.NewRequestWithContext` 复用同一 ctx |
| 10 | `internal/core/compact.go` : `CompactContext` | R3 本体：≤5 条拒绝、成功才替换、取消/失败原历史原封不动、savedTokens=前后估算差 |

## 5. 三种语言的同一场戏：tcode / ccode / gcode

同一个行为规格（轮中 Ctrl+C = 取消本轮），三种语言各自的标准答案：

| 维度 | tcode（TypeScript） | ccode（C#） | gcode（Go） |
| --- | --- | --- | --- |
| 取消原语 | `AbortController`/`AbortSignal` | `CancellationToken` | `context.Context` |
| 传入方式 | `ChatOptions.signal` 字段、`TurnHooks.signal` | `ChatOptions` 属性 + 方法尾参 | 函数**首参** ctx（Go 惯例，`Chat(ctx,...)`、`Run(ctx, args)`） |
| 信号接线 | `rl.on('SIGINT', () => abort.abort())` | `Console.CancelKeyPress` → `cts.Cancel()` | `signal.NotifyContext(ctx, os.Interrupt)` |
| 阻塞点感知 | `fetch(url, { signal })` | `HttpClient.Send(req, token)` | `http.NewRequestWithContext` / `exec.CommandContext` |
| 中止判定 | `err.name === 'AbortError'`（字符串约定） | `catch (OperationCanceledException)` | `errors.Is(err, context.Canceled)`（沿错误链解包，跨包装层最稳） |
| 工具签名 | `run(args, signal)` | `RunAsync(args, token)` | `Run(ctx, args)` |
| 事件形态 | 判别联合（type 字面量成员） | 判别记录/继承 | 扁平 struct + `Type` 判别 |

结论：**取消语义三家一致，差别只在"中止如何被识别"**——TS 靠错误命名、C# 靠异常类型、
Go 靠错误链里的 sentinel（`context.Canceled`），Go 的方案对"错误被层层包装"最有抵抗力。

## 6. 下一步路径

1. 跑一把取消语义：`go run ./cmd/gcode --yolo` 问一个会执行长命令的问题（如 `sleep 30`），轮中按一次 Ctrl+C 观察回到提示符且上下文保留，再按一次观察强退。
2. 读契约测试：`internal/core/turn_test.go` 的四例（规范序列/中止/错误/断尾），改坏 `RunUserTurn` 的事件顺序看哪条先红。
3. 接 usage 事件：`AgentEvent` 已留 `PromptTokens`/`CompletionTokens` 字段，`openai.go` 的 chunk 里就有 `usage`——把它接成 `EvUsage` 事件并在 `renderEvent` 加一行展示。
4. 给 permission 事件找壳：`EvPermission` 已在契约里（id/tool/preview），tcode 的 web 壳用它在浏览器里弹确认框——做 web 壳时即是现成契约。
5. 升级 compact：当前是"纯摘要替换"（`internal/core/compact.go` 文件头注释），"摘要+最近 N 条"的变体等真实需求出现再做。
