# v0.4 移植笔记：R4/R5 与 tcode 第一批能力

> 移植范围：tcode（TypeScript 参照实现）v0.3 → v0.4 的第一批能力 + 蓝图 R4/R5。
> 明确不移植：Plan Mode、apply_patch、Skill 索引、diff 预览（tcode 已走到 v0.5，本单只取 v0.4 范围）。

## 2. C# 惯用表达与 tcode 的差异点

| tcode（TS） | ccode（C#） | 差异说明 |
| --- | --- | --- |
| `skipPermission?: (args, app) => boolean`（可选属性，调用处 `?.`） | `virtual bool SkipPermission(JsonObject args, App app) => false`（虚方法默认 false） | C# 用"虚方法 + 默认实现"表达"可选钩子"，调用处无需空值判断；只有 write/edit override |
| `messages.splice(1, tailStart - 1, summaryMsg)` | `messages.RemoveRange(1, tailStart - 1); messages.Insert(1, summaryMessage);` | List<T> 没有 splice，等价拆成删 + 插两步；语义逐位对齐 |
| `path.resolve(d)` 后再 `filter(d => d.length > 0)` | 先 `Where(!IsNullOrWhiteSpace)` 再 `GetFullPath` | tcode 的顺序有空串陷阱：`path.resolve('')` 返回 cwd，空段会意外把 cwd 加进白名单；ccode 先剔空段再归一化（有意偏离，见第 3 节） |
| `stream_options: { include_usage: true }` 走 `JSON.stringify`（undefined 字段自动消失） | `JsonNode` 手工拼 `body["stream_options"] = ...`，无 JsonIgnore 问题 | 任务书提示的"serialize 时注意 JsonIgnore/条件"在 JsonNode 方案下不存在；字段恒携带，与 tcode 请求体一致 |
| `ev.type === 'message_start' ? ev.message?.usage : ev.usage` | `type == "message_start" ? (ev?["message"] as JsonObject)?["usage"] : ev?["usage"]` | 无类型守卫，用 JsonNode 形状判断；`JsonUtil.Int` 兜底缺字段 |
| `process.exitCode = failed ? 1 : 0` | 顶级语句 `return failed ? 1 : 0;` | C# 顶级语句的返回值即进程退出码，不需要 exitCode 中转变量 |
| `@([^\s@]+)` 正则字面量 | `[GeneratedRegex]` 源生成器（partial 类） | 零依赖前提下拿编译期正则；语义与 JS 同一款非重叠左到右替换 |
| REPL 壳在 tcode 不展开 @引用 | `shell/Repl.cs` 在提交 turn 前展开（任务书要求 REPL 与 exec 共用） | 有意增强：ccode 的 REPL 用户同样享受 @ 注入；命令行（/开头）不展开 |

## 3. 踩坑记录

1. **tcode 白名单空段陷阱**：`[file.allowWriteDirs ?? env.split(delim)].map(resolve).filter(len>0)` 的顺序会让 `''` 段经 `path.resolve('')` 变成 cwd，等于把整个工作目录免确认。ccode 在 `kernel/Config.cs` 里先剔空段再 `GetFullPath`，并留了注释。
2. **`TurnDeps` 属性名撞类型名**：`public App? App { get; init; }` 在 C# 完全合法（属性名与类型名同名的成员场景），比起别名 `AppContext`（与 `System.AppContext` 撞）反而更干净。
3. **`Path.DirectorySeparatorChar` 判定**：白名单用 `target == root || target.StartsWith(root + sep)`，前提是两边都过 `Path.GetFullPath`（Windows 会把 `/` 归一成 `\`），否则混合斜杠会漏判。测试里补了一条相对路径归一化用例锁住该行为。
4. **80% 双档对既有测试无扰动**：`EventTests`/`CompactTests` 的假 App 用 `ContextLimit = 1_000_000`，治理永不触发；调阈值不需要改任何既有断言，验证了"治理只看估算 vs 阈值"的接缝干净。
5. **exec 的权限闸门留空**：exec 强制 yolo 后 `TurnHooks.Check = null`（AgentLoop 视为全放行），与 tcode main.ts 一致——无交互环境没有"问"的能力，唯一的安全边界就是启动时的 --yolo 强制。

- TDD 先红：桩实现（SkipPermission 恒 false、AtRefs 恒等、/approval 空操作）下运行 `dotnet run --project tests`，10 条新断言全红：`43 通过 / 10 失败`。
