# 学习指南：事件模型与上下文压缩（AgentEvent 与 compact）

> 对应实现：ccode（C# / .NET 8）v0.3，移植自 tcode 的 R1/R3。读完你应该能回答：
> 为什么"壳渲染什么"不再取决于回调参数表而取决于事件类型；为什么 compact 失败永远不会
> 毁掉会话历史；以及 TS 的可辨识联合在 C# 里用什么结构表达。

## 1. 一句话定义

**事件模型 = 把"一轮对话中发生的事"定义成一组封闭的、可判别的记录（AgentEvent），
turn 是唯一的生产者，壳/审计/测试只靠 switch 消费——加功能 = 加事件变体，不动消费端接口。**
**compact = 调当前模型把旧对话压成一份任务摘要，成功才用 `[system, 摘要]` 替换全部历史；
失败或取消时历史原封不动，它是裁剪（trim）的上策，trim 降级为它的兜底。**

## 2. 核心要素与类比

| 要素 | 类比 | 在 ccode 里的落点 |
| --- | --- | --- |
| `AgentEvent`（抽象 record） | 电台的统一频道编码：所有节目（事件）走同一条广播线 | `kernel/Types.cs`：`abstract record AgentEvent` + 10 个嵌套 `sealed record` 变体 |
| `TurnHooks.Emit`（`Action<AgentEvent>?`） | 收音机：生产者只管播音，听众自己接 | `core/Turn.cs` 的 `TurnHooks`；壳在 `shell/Repl.cs` 传 `Emit = Render` |
| `TurnEndReason`（枚举） | 结账小票上的三种状态：买单/离席/摔杯子 | `kernel/Types.cs`：`enum TurnEndReason { Completed, Aborted, Error }` |
| 生产者唯一 | 一轮对话只有一个人讲故事，别人转述免谈 | `core/Turn.cs` 是唯一 emit 点，`AgentLoop` 仍只出回调（`callId` 由 turn 包装成事件） |
| `Compact.CompactContextAsync` | 请一个速记员把 200 页会议记录缩成一页纪要 | `core/Compact.cs`：返回省下的 token 数（`int`） |
| `MinMessages = 5` | 两页纸不值得请速记员 | `core/Compact.cs`：`messages.Count <= 5` 直接抛"对话太短，没什么可压缩的" |
| "先算后改" | 速记员交稿前，原件一张不丢 | 摘要成功后才 `RemoveRange` 替换；失败/取消抛异常，历史原样 |

## 3. 点破三个常见误解

| 误解 | 事实 |
| --- | --- |
| "C# 没有可辨识联合，事件流这种 TS 惯用法没法搬" | 搬得动：`abstract record` + 嵌套 `sealed record` 就是判别联合。运行时判别靠类型（`case AgentEvent.ToolCall call`），穷举靠 switch 表达式，形状不可变靠 `sealed` + `record` 值相等。tcode 的 `{ type: 'tool_call', call_id, ... }` 与 `AgentEvent.ToolCall(CallId, Name, Args)` 一一对应 |
| "compact 失败了至少该删掉一部分旧消息吧" | 恰恰相反：compact 的纪律是**成功才动手**。`core/Compact.cs` 先 `EstimateTokens` 计算前后差、请求摘要，全部成功才 `RemoveRange` 替换；摘要请求抛异常（网络错/取消/空摘要）时函数早已退出，一条消息都没碰。会话文件也因此不会出现"压了一半"的中间态 |
| "轮前治理 = 每轮都裁剪" | 现在是两级：先估 token（与 Trim 同式，`core/Trim.cs` 的 `EstimateTokens`），**超限才**先试 compact；compact 失败（含太短/网络错）再退 `Trim.TrimContext` 裁旧工具输出。trim 从"常规操作"降级为"兜底" |

## 4. 本仓库的真实实现（读代码顺序）

1. **事件契约** — `kernel/Types.cs`
   `enum TurnEndReason`；`abstract record AgentEvent` 内嵌 10 个变体：
   `TurnStart(Id)` / `User(Text)` / `TextDelta(Delta)` / `ToolCall(CallId, Name, Args)` /
   `ToolResult(CallId, Name, Summary, Ms)` / `Permission(Id, Tool, Preview)`（占位）/
   `Trimmed(Count)` / `Compact(SavedTokens)` / `Usage(...)`（占位）/ `TurnEnd(Reason, Error = null)`。
2. **生产者** — `core/Turn.cs` 的 `RunUserTurnAsync(app, line, hooks, cancellationToken)`
   发射顺序：轮前治理（超限 → `Compact` 事件，失败退 `Trimmed` 事件）→ `TurnStart(Guid)` →
   `User(line)` → 循环内 `TextDelta`/`ToolCall`/`ToolResult` → `TurnEnd(Reason)`。
   异常路径：`OperationCanceledException` → `TurnEnd(Aborted)` 后上抛；其他异常 →
   `TurnEnd(Error, e.Message)` 后上抛；两条路都先走 `RepairTail` 断尾修复 + `AppendSince` 落盘
   （与 v0.2 的落盘语义完全一致）。
3. **回调 → 事件的接缝** — `core/AgentLoop.cs` 的 `TurnDeps`
   循环本身仍出散回调：`OnToolCall(callId, name, args)`、`OnToolResult(callId, name, result, ms)`
   （本版新增 callId 参数）；`Turn.cs` 把它们包装成 `AgentEvent`——
   `ToolResult` 的 `Summary` 取 `result.Split('\n')[0]`，与 tcode 的 turn.ts 同构。
4. **消费者** — `shell/Repl.cs` 的 `Render(AgentEvent)`
   只处理四个变体：`TextDelta` 直写、`ToolCall` 打 `⚙ 名称 参数`、`ToolResult` 打
   `↳ 首行 (ms)`、`Trimmed` 打灰字提示；其余变体静默（横幅/提示符/命令自己承担）。
   渲染输出与 v0.2 逐字一致——事件化没有改变壳的行为，`tests/Smoke.cs` 五场景全绿是回归证明。
   同文件的三态 Ctrl+C 路由（`LineSource`/`CancelKeyPress`/`CancellationToken`）原样保留。
5. **手动压缩** — `plugins/commands/Compact.cs`（注册于 `plugins/PluginList.cs`，yolo 与 exit 之间）
   `/compact` 调 `Compact.CompactContextAsync(app)`；成功打
   `已压缩：替换为任务摘要，节省约 N tokens 的上下文预算。`，失败打 `压缩未执行：...` 且不上抛。
6. **压缩本体** — `core/Compact.cs` 的 `CompactContextAsync`
   ≤5 条抛"对话太短，没什么可压缩的"；transcript = `messages[1:]` 的 `"role: content"` 逐行拼接
   （assistant 带 tool_calls 时显示 `(tool_calls: N 个)`）；摘要请求是两条消息
   （system "你是会话摘要器……" + user 摘要指令与 transcript），`CancellationToken` 装进
   `ChatOptions` 一路贯通到 `providers/OpenAi.cs` 的 `SendAsync`/SSE 读循环——
   轮中 Ctrl+C 连摘要请求都能真取消；成功才 `RemoveRange(1, count-1)` 换成
   `[system, user "[此前对话的摘要——当前任务以此为背景继续]\n摘要\n[摘要结束]"]`。
7. **测试锁约** — `tests/EventTests.cs`（镜像 tcode/test/events.test.ts）
   两段式假客户端断言规范序列 `TurnStart→User→ToolCall→ToolResult→TextDelta→TurnEnd(Completed)`；
   预取消令牌断言 `TurnEnd(Aborted)` + 上抛 `OperationCanceledException`；普通错误断言
   `TurnEnd(Error, "网络炸了")`；断尾修复与事件互不干扰。
   `tests/CompactTests.cs` 四例：替换+saved>0 / 太短拒绝原状 / 失败原状 / 取消原状。

## 5. 行业对照：判别联合在不同语言里怎么表达

| 语言/实现 | 事件"变体"的表达 | ccode/tcode 对照 |
| --- | --- | --- |
| TypeScript（tcode） | 可辨识联合：对象字面量 + 字面量字段 `type` 判别 | `kernel/types.ts` 的 `AgentEvent = { type: 'turn_start'; id } \| ...`；收窄靠 `ev.type === 'tool_call'` |
| C#（ccode） | 抽象基类 + 嵌套 sealed record，类型即判别字段 | `kernel/Types.cs` 的 `abstract record AgentEvent`；收窄靠 `switch (ev) { case AgentEvent.ToolCall call: ... }`；`sealed` 禁止变体再被继承，`record` 免写相等性 |
| Go（gcode 同族） | 结构体 + interface{}，运行时类型断言 | 常见做法是 `type AgentEvent struct { Type string; ... }` 大平铺或 `interface { isAgentEvent() }` 标记接口，穷举性没有编译期保障 |
| Rust（rcode 同规格） | `enum AgentEvent { TurnStart { id: String }, ... }` | 语言级代数数据类型，`match` 强制穷举——C# 的 record 层级是最接近的仿写 |

规律：**变体数量封闭、消费端必须逐变体处理的需求，用"和类型"表达最省心**。
TS 用字面量字段模拟、Go 只能靠约定、C# 用 record 层级 + 模式匹配、Rust 原生 enum。
ccode 选 record 层级而不是 `record AgentEvent(string Type, ...)` 大平铺，
正是为了把"非法事件形状"挡在编译期。
