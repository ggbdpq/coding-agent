## 二、本轮确定的契约

| # | 问题 | 结论与边界 | 依据 |
| --- | --- | --- | --- |
| 1 | 执行中的输入 | 保留可编辑草稿；用户显式“排队下一条”，仅一个待执行条目，可取消。当前完整轮次（含 afterTurn）成功结束后串行执行。 | 本轮工程默认；复用单执行器与 busy 锁 |
| 2 | 失败与停止 | 模型、准备步骤或任一 Hook 失败不继续队列；停止立即取消待执行条目。取消原因及原文本进入活动历史；显式取消在当前输入为空时回填，不覆盖新草稿。 | 真实 HTTP/SSE、实际审批与文件结果回归 |
| 3 | 刷新与重启 | 同一服务通过 GET /state 和 SSE 恢复等待队列；队列只在内存中，重启不自动执行。 | 有界单槽，不增加持久化调度器 |
| 4 | 网络重试 | 请求绑定原会话、完整轮次 owner 和 id。结果不明时确认原请求，跨轮或空闲不自动转成新输入；取消后的新意图生成新 id，同轮旧 id 不能复活。 | 公开回归锁定丢失回执与重复执行 |
| 5 | 新会话与明确拒绝 | 显式新建/切换会话或工作区清除旧确认意图；旧 ACK 迟到仅确认原请求，不清新上下文草稿或回切页面。首次排队明确被 4xx 拒绝后保留草稿，允许按新状态发送。已进入确认的请求不因拒绝自动重发。 | 避免跨会话吞输入和结束竞态下的确认死路 |
| 6 | 审查范围 | “仓库全部变更”及“本轮快照文件”。后者只筛选有效快照路径；两种 diff 都相对 HEAD，包含同一路径的用户修改，不是 Agent 独占差异。 | 复用 changes.revertable，不新增归属模型 |
| 7 | 撤销与提交 | 撤销仍恢复本轮首次写前内容并校验写后指纹；路径身份在成功写入时固定为物理路径，符号链接重指不能转移旧快照。筛选只影响展示，提交仍覆盖仓库全部已暂存文件。 | 真实 Git index/文件字节回归 |
| 8 | 快照缺口 | bash 写入、超大原文和失败写入不提供有效快照；旧日志中无法证明原物理目标的软链路径不作安全撤销。 | 显式能力边界；不重建跨轮任务基线 |

本切片无待用户拍板的阻断项。B 多项目/任务组织及 C 技能/MCP/扩展管理保留为后续候选，需要各自定义验收范围。

## 三、明确不做

| # | 排除项 | 原因 |
| --- | --- | --- |
| 1 | 即时干预、跨轮任务基线、多会话并行、持久化指令队列及 B/C 全量改造 | 本轮仅批准单任务执行与审查；单槽串行已满足当前验收。 |
| 2 | 重建已有目录选择、设置中心和基础 Git 操作 | 现有实现已具备且本轮回归覆盖；后续应围绕实际缺口。 |
| 3 | 把仓库 HEAD diff 称为“Agent 本任务 diff” | 它包含用户及其他未提交编辑，不能据此证明归属。 |
| 4 | 放开 busy 保护来模拟并行或即时干预 | 当前切会话会更换执行上下文；排队、只读浏览与并发是不同契约。 |
| 5 | 用动画、百分比或按钮占位代替实际命令进度 | 状态应来自真实执行事件；缺事件时先明确能力边界。 |
