# 学习指南：给一个项目改名，到底在改什么

> 对应提交：`8a492af78`（gcode → tcode 全量改名）。读完后你应该能独立完成一次
> 不留尾巴的项目改名。

## 一句话定义

项目改名不是改文件夹名，而是把"这个名字出现的每一个**契约现场**"全部换掉——目录只是其中最不起眼的一处。

## 三个核心要素（配类比）

1. **机器契约**（类比：你搬家后所有快递单上的地址）。环境变量 `GCODE_*→TCODE_*`、
   配置目录 `~/.gcode→~/.tcode`、二进制名 `bin/gcode.js`、包名 `package.json` 的
   `name`/`bin` 字段。这些东西不改，程序直接跑不起来——它们是最容易发现、也最该先改的。
2. **用户可见身份**（类比：公司 logo）。终端横幅 `tcode v0.2.0`、REPL 提示符 `tcode❯`、
   系统提示词里的自称"你是 tcode"、桌面窗口标题、错误页文案。不改不报错，但很精神分裂。
3. **文档与身份残留**（类比：旧名片）。README/ARCHITECTURE 是活文档要全改；
   **带日期的决策记录（docs/notes/）是历史档案，刻意不改**——它记录的是"当时叫 gcode
   时做的决定"，改了反而是篡改留痕。

## 最容易混淆的误解

"我用 IDE 的全局替换一下就完事了。"——错在两层：一是大小写变体（`gcode`/`GCODE_`/
`Gcode`）需要分别替换，`gcode` 的小写替换**不会**命中环境变量前缀 `GCODE_`，本次就因此
让冒烟场景 A 起不来（进程报缺少 TCODE_API_KEY，因为脚本还在传 GCODE_API_KEY）；
二是 `--include` 漏了扩展名，第一轮 grep 没扫 `*.html`，导致 web UI 页面标题漏改。

## 本次改名的实际清单（可复用的 checklist）

| 层 | 项目 | 本案位置 |
| --- | --- | --- |
| 仓库 | `git mv` 目录 + 历史 bundle 改名 | `vibe/agent/tcode/`、`tcode-history.bundle` |
| 机器契约 | 环境变量前缀 | `TCODE_API_KEY/BASE_URL/MODEL/PROTOCOL/CONTEXT_LIMIT/BASH` |
| 机器契约 | 配置目录 | `~/.tcode/`（`mv ~/.gcode ~/.tcode`，会话保留） |
| 机器契约 | 入口与包名 | `bin/tcode.js`、package.json `name`/`bin`、两份 lock 重生成 |
| 用户可见 | 横幅/提示符/自称 | `shell/repl.ts`、`shell/web.ts`、`shell/web.html`、`systemprompt.ts` |
| 桌面壳 | Cargo 包名/productName/identifier | `desktop/`（改完必须**清 target 重编译**：旧缓存里烘焙了旧绝对路径） |
| 文档 | 活文档全改、历史记录不改 | README/ARCHITECTURE 改；`docs/notes/` 不改 |
| 外部引用 | 上层仓库索引 | guahub 根 README 的项目表/备份表/治理日志（日志追加新条目不改旧条目） |

## 行业现实

npm 包改名走 `npm deprecate` + `passes the torch` 字段（lodash→lodash-es 式）；Go module
改名要同时改所有 import 路径（所以大项目能不改就不改）；大厂做法是"新名字 + 旧名永久
alias"（如 Twitter/X），因为外部契约改不动。个人项目最幸福——可以像本案一样断得干净，
**不留任何兼容别名**，这是只有在没人依赖你时才享受得起的自由。
