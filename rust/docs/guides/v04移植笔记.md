# v0.4 移植笔记：tcode R4/R5 与 v0.4 第一批 → rcode

面向读者：对照着 tcode（TypeScript 参照实现，已是 v0.5.0）读 rcode（Rust 版，
serde_json + ureq 两个直接依赖）的人。先给结论：**本次把 tcode 的 R4（审批策略 +
写白名单）、R5（usage 事件）与 v0.4 第一批（compact 尾部保留、80% 双档治理、
exec 无交互、@引用、--continue、/sessions、/init）移植进 rcode，版本 0.3.0 → 0.4.0，
`cargo test` 全绿（41 单测 + 7 冒烟，含新增场景 H）。** 只移植 v0.3→v0.4 范围：
tcode 的 Plan Mode / apply_patch / Skill 索引 / diff 预览一律不碰。

## 2. Rust 惯用表达与 tcode 的差异点

| tcode（TS） | rcode（Rust） | 为什么 |
| --- | --- | --- |
| `skipPermission?:` 可选方法 | `skip_permission: Option<Rc<dyn Fn(&Value, &App) -> bool>>`，None=必问 | rcode 的插件是"结构体 + 回调字段"而非 class 继承；Option 即"未声明"，agentloop 判 None 后走闸门 |
| `deps.app?: App` 挂在 TurnDeps | `run_turn(app: &mut App, deps)` 整体传 App | 借用检查不允许"deps 持 `&App` + 同时借 `&mut app.messages`"（同一结构体的整体不可变借用与字段可变借用冲突）；消息、工具、白名单环境都从 `&mut App` 拿，见 `src/core/agentloop.rs` 头注 |
| `@([^\s@]+)` 正则替换 | 手写 char 扫描（`@` 起点判定 + token 收集） | 依赖政策不引 regex crate；对齐语义：`@` 须在行首或空白后，token 不含空白与 `@`，孤立 `@` 原样 |
| `content.length > 256*1024`（UTF-16 码元） | `content.chars().count()`（按 char 截断） | ASCII 场景数值一致，CJK 不劈半个字，比 JS 更准 |
| `approval?: 'normal' \| 'never'` | `approval: Option<String>`，None=normal，装载时校验 | 任务口径：只允许 normal/never，默认 None 即 normal；`/approval never` 运行时写回 `Some("never")` |
| `path.resolve(d)` 后过滤空串 | **先滤空段再归一**（`to_absolute`） | tcode 的 `path.resolve('')` 返回 cwd——`ALLOW_WRITE=a;;b` 会把 cwd 静默收进白名单；rcode 把过滤提前堵掉这个洞 |
| `path.delimiter`（平台相关） | 固定 `;` 分隔 `RCODE_ALLOW_WRITE` | rcode 以 Windows 为第一目标（会话文件名同样做了 Windows 化）；需要跨平台时再按 cfg 切 |
| 词法归一靠 `path.resolve` | `src/kernel/config.rs` 的 `to_absolute`：拼 cwd + 消化 `.`/`..`，不触盘 | kernel 不反向依赖 plugins/pathguard，自持最小实现；不用 `canonicalize`（触盘、且 Windows 返回 `\\?\` 前缀会破坏前缀比较） |
| `messages.splice(1, tailStart-1, summaryMsg)` | `tail.to_vec()` 先克隆 → `truncate(1)` → push 摘要 → extend 尾部 | compact 的纪律是"失败原封不动"，先把尾巴克隆出来再改历史，所有权模型下最直白 |
| `usage: {prompt_tokens, completion_tokens}` 匿名对象 | `pub struct Usage { prompt_tokens: u64, completion_tokens: u64 }` | 具名 struct 可演化（将来加 total_tokens 不改回调签名） |
| `AgentEvent` 判别联合加变体 | `AgentEvent::Compact { saved_tokens }` 新增变体 | Rust enum 天然是判别联合：match 穷尽检查逼着每个消费端显式表态（REPL 渲染、exec 忽略、测试的 event_type） |
| `process.exitCode = failed ? 1 : 0` | `std::process::exit(1)` + 显式 `stdout().flush()` | `process::exit` 不走运行时的 stdout 清理，TextDelta 的 `print!` 残留缓冲必须手工 flush，否则 exec 的回答可能被截断 |
| `--approval normal|never` CLI 旗标 | 不移植旗标；`RCODE_APPROVAL` 环境变量 + `/approval` 命令 | 与 gcode 同口径：少一个旗标少一套"参数规整跳过 -- 值"的解析 |

## 3. 踩坑记录

1. **openai usage 分片会被 choices 判空吃掉**。`stream_options.include_usage` 的
   usage 分片 `choices` 为空，移植前的解析先看 `choices[0].delta`——usage 解析若放
   在后面且不先独立消费，流末尾的用量永远收不到。rcode 的 SSE 解析用
   `chunk["choices"][0]["delta"]` 直接下标（空数组取下标得 Null，不 panic），但
   usage 消费仍明确放在 delta 之前，见 `src/providers/openai.rs` 的注释锚点。
2. **尾部切片点的扫描方向以测试断言为准**。任务文本写"从 len-4 向前扫描"，但
   `tcode/test/compact.test.ts` 的断言是：len-4 恰为 tool 消息时，尾部从其后最近的
   user 开始、总长 5 条——即**从 idealStart 向后**扫（`pick_tail_start` 的 skip 递增）。
   两个方向都"配对安全"，保留条数却不同；照抄断言，不照抄描述。
3. **`&mut App` 借用冲突是本次最大的结构性差异**。最初想把 `app: Option<&App>`
   放进 TurnDeps 对齐 tcode，`run_turn(&mut app.messages, &deps)` 直接 E0502：
   `&*app` 是整体重借用，与 `&mut app.messages` 的字段借用不能共存。解法是把
   `run_turn` 改签名为收 `&mut App`（provider/tools 用 `Rc` clone 出来避免长期持借），
   skip_permission 调用点临时 `&mut T → &T` 强制coerce，见 `src/core/agentloop.rs`。
4. **Anthropic 的 usage 是"逐事件给值"**：message_start 给 input/output 初值，
   message_delta 给累计 output；不是 openai 的"流末一个分片"。移植沿用 tcode 的
   逐事件回调，不做"合流后再上报"的伪优化。
5. **本机 Git Bash 用 heredoc 向 .rs 文件追加代码时 `\\` 会被吃成 `\`**：白名单
   测试里写 `"E:\\definitely\\..."` 落盘变成单反斜杠（非法转义）。改用真实临时目录
   构造路径（`temp_dir()` + `Path::join`）后既绕开转义又让测试平台无关。
6. **`/approval` 切换必须同步 yolo**：rcode 的闸门（`core/permission.rs`）只认
   `App.yolo`，`/approval never` 若只改 `config.approval` 就是假生效。切换时
   never≡yolo 开、normal≡yolo 关，与 /yolo 语义互锁（gcode 同款教训）。

## 4. 与 tcode 的行为差异（有意为之）

- `/approval` 是 rcode 新增命令（tcode 只有 CLI 旗标）；切换时同步 yolo 开关。
- `RCODE_ALLOW_WRITE` 空段不收 cwd（tcode 会）；config.json `allowWriteDirs`
  优先于环境变量，与 tcode 一致。
- bash/web_fetch 两端都不设白名单：命令级操作无法按路径约束，逐次确认不放松。
- usage/compact 事件在 exec 渲染器中忽略（对齐 tcode 的 default 分支）；REPL
  对 compact 渲染一行 dim 提示、usage 静默。
- exec 出错路径上 tcode 不补打换行、rcode 同样只在成功路径补 `\n`。
- `--continue` 恢复后打新会话文件（`resumedFrom` 标记来源），与 `/resume 1`
  同语义——这是 rcode v0.3 就有的落盘纪律，tcode 的 /resume 同款。
