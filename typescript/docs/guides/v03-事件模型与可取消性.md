# 学习指南：tcode v0.3 的事件模型、可取消性与上下文压缩

> 面向读者：读过 tcode 代码（或学过 `docs/guides/学习指南.md` 之外的任一语言版），
> 想理解 v0.3 三个核心升级怎么落地。所有路径与成员名都是本仓库真实位置。

## 1. 一句话定义

v0.3 做了三件事：**把轮内发生的一切变成事件**（AgentEvent）、**让取消信号流进每个工具**
（AbortSignal 贯穿）、**让长会话靠摘要而不是丢历史续命**（/compact）。

## 2. 三个核心要素（配类比）

| 要素 | 类比 | 落点 |
| --- | --- | --- |
| AgentEvent | 会议纪要：turn 是记录员，屏幕上发生的一切都先落成纪要条目，看板（REPL/网页）只照着纪要念 | `src/kernel/types.ts` 的 `AgentEvent` 联合类型 + `src/core/turn.ts` 的 `emit` |
| AbortSignal | 电闸拉闸：用户拉闸，信号沿线传导，每个用电器（HTTP 请求、子进程）自己决定怎么断电 | `src/plugins/tools/bash.ts` 的 abort 分支、`src/plugins/tools/webfetch.ts` 的 `AbortSignal.any` |
| /compact | 会议纪要的"上集回顾"：把前 40 分钟压成一段话，只带着结论开下半场 | `src/core/compact.ts` + `src/plugins/commands/compact.ts` |

## 3. 最容易混淆的误解

**误解："取消 = 杀进程。"** 杀进程是最粗的取消。协作式取消是把同一个"取消令牌"
传进每一个可能阻塞的操作——HTTP 请求自己断、子进程自己死、循环自己检查。看
`src/plugins/tools/bash.ts`：`spawn` 的超时定时器与用户中止共用一个杀树分支，
但用 `killed`/`aborted` 两个标志区分"超时强制终止"与"用户中止"，退出报告如实区分。
另一个误解是"事件模型要上 EventEmitter/消息总线"——一个
`emit: (ev: AgentEvent) => void` 函数就是完整的事件出口（`src/core/turn.ts:11`）。

## 4. 结合本仓库的调用链

- 事件流：`shell/repl.ts` 的 `renderToTerminal` 与 `shell/web.ts` 的 `bridgeEvent`
  各自消费 `runUserTurn(app, line, { emit })` 吐出的同一串事件——REPL 直写终端，
  web 翻译成既有 SSE 线协议（`test/smoke.mjs` E1/E2 因此零改动全绿，这就是
  "线协议不变"的实证）。
- 上下文治理：`src/core/turn.ts` 轮前先看估算 token，超限先 `compactContext`
  （失败退回 `trimContext`）；手动 `/compact` 走 `plugins/commands/compact.ts`。
- 审批策略：`src/kernel/config.ts` 的 `approval: 'normal'|'never'`（`--approval` 或
  config.json）与 `allowWriteDirs` 白名单；工具侧声明
  `skipPermission(args, app)`（`plugins/tools/write.ts`/`edit.ts`），
  agentloop 在闸门前先问它（`src/core/agentloop.ts` 的 allowed 判定）。

## 5. 行业对比

Codex 把 compact 做成了十余个模块的系统（token 预算/远端摘要/回退），把沙箱做成
OS 级原语——那是给百万用户的成熟度。MiniMax Code 的 EventBridge 同样是
"内部事件 → 展示事件"的翻译层（`packages/agent-core/src/event-bridge/`），我们的
web.ts `bridgeEvent` 是它的单文件形。ZCode 的 Hooks 与我们的三 hook（R5 将接入
beforeTool/afterTool）同构。**事件模型的价值不在规模，在"加功能只加事件类型"。**
