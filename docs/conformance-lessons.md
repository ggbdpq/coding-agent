# conformance-lessons —— 一致性工程失效案例与不变量

本文件只记录一类东西：**验证体系自身怎么失效**——真实案例 + 由此固化的不变量。
行为差异记录归 specs/（允许偏差表）与将来的 conformance 报告，不进这里。
追加纪律：一个案例必须提炼出一条可执行的不变量，否则不配入册。

---

## L1 · Build Freshness Invariant（构建新鲜度不变量）

**不变量：一致性验证的有效性，以"跑的是刚构建的被测产物"为前提。执行层必须在运行前证明
产物新鲜度；单测绿不能为可执行层背书。**

### 案例（2026-10-01 审计；同款问题首次发生于 2026-09-27，ADR-001 后果节已登记）

现象链：

```text
Unit Test Green      rcode 单测 55/55 全绿
        ↓
Executable Smoke Red 冒烟 7/7 全红："启动子进程失败 NotFound(3) 系统找不到指定的路径"
        ↓
Root Cause           CARGO_BIN_EXE_rcode 是编译期嵌入的绝对路径；缓存的 smoke 测试
                     二进制内嵌了失效旧路径，cargo 指纹未判其失效
        ↓
Fix                  touch tests/smoke.rs 强制重编译 → 7/7 全绿
```

诊断过程的价值：手写同形态探针（`Command::env_clear + envs + current_dir` 四变体）全绿 →
排除代码与环境；逐字复制 `start_proc` 链路仍绿 → 锁定差异不在代码而在**测试二进制产物本身**
→ `touch` 重编译验证闭环。整个过程约 40 分钟，若无"逐字对照"方法论，最可能的错误结论是
"rcode 行为漂移"——恰恰写反。

### 为什么它是一致性工程的第一课

1. **两层证据不可互相替代**：单测（进程内、经注入）与可执行冒烟（子进程黑盒）失效模式完全
   不同，前者全绿对后者零背书；
2. **失效是静默且误导的**：报错指向"启动子进程失败"，与真实根因（产物陈旧）相距甚远；
   排查天然滑向"行为漂移"的错误方向；
3. **人工守护不可持续**：ADR-001 登记后一个月内复发——登记不产生免疫力，**只有把新鲜度
   检查做进执行入口才免疫**。

### 落点

conformance runner 的第一约束（Phase 2 设计）：五个适配器执行场景前必须经过**构建新鲜度门**
（强制重建或校验产物时间戳/路径有效性），门失败输出的是基建错误，不计入行为比对结果。

## L2 · Environment Premise Expiry（环境前提过期）

**不变量：验证欠账的登记必须携带可复核的环境前提；前提变化时，欠账要么复跑清零，要么显式
降级——人工登记会过期，自动化不会。**

### 案例（2026-10-01 审计）

specs/ 七篇规范低置信区反复登记"ccode 本机无 .NET SDK，未复跑"（2026-09-27 登记）。2026-10-01
发现 dotnet 8.0.425 已就绪，`dotnet run --project tests` 首跑 **63/63 全绿**——含 spec 明文
标注"从未编译运行"的 TrimTests 空内容用例。欠账瞬间清零，但它也意味着：**在此之前，家族
五分之一的验证面处于"无人知道是否还绿"的状态长达数日**，且没有任何信号提醒前提已变。

### 教训

1. "暂不验证"的登记没有失效预警，会静默地从"环境暂缺"腐化为"默认没人管"；
2. 欠账清零的收益是即时的、一次性的——同类欠账应当被结构性消灭，而非逐条跟踪。

### 落点

一致性层进入 CI 后，"本机缺 X SDK"类欠账失去存在理由：runner 所在环境（或 CI 矩阵）就是
验证前提的常驻保证。Phase 2 设计要求：适配器声明自身环境前提，前提不满足时报**基建错误**
（区分于行为失败），使欠账显式化、可报警。
