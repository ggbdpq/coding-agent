# ADR-002 —— 可执行一致性层（Introduce Executable Conformance Layer）

- 状态：已接受（2026-10-01）
- 决策人：用户（Executable Conformance Engineering Phase 1 启动令 + 2026-10-01 一致性审计证据）
- 本 ADR 激活 [ADR-001](ADR-001-目录收口.md) 决策 5 的搁置条目"冒烟契约上浮（conformance）"，
  并在 [docs/从零到一到一百.md](../从零到一到一百.md) §3.3 注销该条目。

## 背景

五个 runtime（impls/ 五语言）与 specs/ 正文 v1 均已成立；跨版一致性目前由"五份语言内联
冒烟副本 + 人工对照笔记"保证，行为规范没有机器验证。2026-10-01 一致性审计
（[docs/conformance-audit.md](../conformance-audit.md)）给出三项证据：

1. **可执行层会静默失效**：rcode 冒烟 7/7 全红而单测 55 全绿，根因是编译期烧进测试二进制的
   绝对路径随缓存陈旧而失效（同款问题 ADR-001 已登记过一次，本日复发）——"五份副本各自为政"
   的验证面连自身的有效性都需要人工守护；
2. **场景集已跨版分化**：/compact 冒烟仅 gcode 有、exec 反例 H₂ 仅 gcode/rcode 有、
   --continue 无专项场景——副本之间不再覆盖同一行为面；
3. **验证欠账随环境漂移累积**："ccode 缺 .NET SDK"在七篇规范低置信区重复登记，dotnet 就绪后
   一次实跑即 63/63 清零——人工登记的验证欠账没有过期预警。

搁置条目的启动条件（"场景跨版漂移"）已成立，且用户裁定启动。

## 参照

- `E:\ggbdpq\gh\language`（ADR-001 双参照之一）：根级 conformance 独立契约套件、
  裁决链 specs > conformance > 参考实现。
- [docs/conformance-audit.md](../conformance-audit.md)：本仓自己的证据。

## 决策

1. 引入根层 `conformance/`——**可执行一致性层**。单一职责：验证**同一个 scenario 在不同
   runtime 中产生等价行为**，并以机器可读的 pass/fail 与 diff 报告输出。
2. 层形态（语言中立，不含实现选型）：**scenario**（描述行为，不描述实现）→
   **runtime adapter**（每版一个薄适配，runner 不感知五种语言）→ **normalizer**
   （各版原始输出归一为 canonical 形态）→ **diff / 报告**（跨版等价判定）。
3. 裁决链更新：**specs > conformance > tcode 源码（参考实现）> 笔记**。conformance 是
   specs 的机器可执行面，接管 specs/README 写作约定 2 的跨版验收职责；五版自有冒烟保留为
   各版回归套件，不再承担跨版一致性职责。
4. 首批场景 ≤5，从高价值行为与审计覆盖缺口中选取（Plan Mode / apply_patch / tool error /
   invalid input / cancellation）；cancellation 因平台允许偏差（py+rs 无轮中取消）按
   **分档断言**表达，不强行统一。具体清单在 Scenario Schema 设计文档中冻结。
5. schema 格式、adapter 接口、归一化口径、runner 宿主语言、CI 形态属实现设计，在接受本 ADR
   后以设计文档冻结，不在本 ADR 展开。

## Non Goals

- 不负责 Agent 功能开发、runtime 重构、新语言支持；
- 不做性能 benchmark、UI/web 壳测试（E1/E2 留在 tcode 自有冒烟）；
- 不追求 100% 覆盖——目标是证明行为一致，不是做成测试项目；
- 不消除已登记的平台允许偏差（一致性以"分档断言 + 偏差登记"表达，不强行拉齐实现）；
- 不取代各版单测与冒烟（它们继续守护各版内部回归）。

## 后果

- + 漂移由机器发现：规范变更的跨版回归从"人肉同步五份冒烟"降为"更新场景源一份"；
- + spec 成为真 SSOT：行为规则第一次拥有唯一份、可机器执行的真值载体；
- + 新语言版获得客观入门验收（跑绿同一套件即一致，对应从零到一操作手册）；
- + 平台侧验证欠账可入 CI（ubuntu）一次性补红能力（如 rust 分隔符契约在 Windows 上恒绿无判别力）;
- − runner/adapter/normalizer 自身成为新维护面：五个适配器随五版 CLI 演化，exec 模式自此从
  "内部能力"升格为**被一致性契约锁定的公共接口**，其行为变更产生兼容性义务；
- − 归一化口径是最大设计风险：分档不当会把"语言惯用差异"误判为漂移（或反之掩盖真漂移），
  Scenario Schema 设计文档必须给出归一化规则的反例清单。

## 验证

本 ADR 为决策记录，无代码变更。实施验证归属 Scenario Schema 与 Runner 的后续交付：
单一场景贯通五版、跨版 diff 报告为零意外分歧（或分歧均可归类到已登记允许偏差），方可视为
本决策落地。
