# ADR-003 —— 轮内控制点：中间件钩子下沉到每次模型调用

- 状态：提议（WP0 起草；各工作包合并时逐条定稿，见 specs/ 各文件"修订草案"段落）
- 决策人：架构重构（refactor/arch-langchain）
- 评审依据：`docs/arch-refactor/`（00-评审、01-目标架构、02-接口契约）

## 背景

上下文治理、熔断、权限、持久化都只挂在"轮"这一层；而一轮最多可以有
`MAX_TOOL_ROUNDS + 1` 次模型调用（缺省 41）。复现脚本（arch-refactor 附录 A）
可见单轮请求 tokens 从 9 涨到 160145，4 次突破 100000；参数非法被静默降级为
`{}`；40 轮熔断无事件；会话只在轮末落盘，进程崩溃丢整轮。

五个差距的共同根因：**控制点挂错了层**，不是缺功能。

## 决策

1. core 引入 `TurnMiddleware`（`beforeModel / afterModel / wrapToolCall`），
   由 turn 按固定顺序组装，**不进插件注册表**（"loop 不插件化"Q4 决策不变，
   安全边界不可替换）。
2. 权限闸门固定在最内层；Plan Mode 迁移为 `wrapToolCall` 中间件，行为不变。
3. 上下文治理 = 清理旧工具输出 → 压缩 → 裁剪，触发点从"轮前"扩展为
   "轮前 + 每次模型调用前"。
4. 工具参数非法不再静默变 `{}`：不执行工具，回灌固定话术并发 `tool_error`
   事件（修订 agent-loop R4，新增第六出口）。
5. 审批新增第四态 `scoped`，按授权键记忆（permission R2 增量）；
   **R3 的 always 语义不变**（进程内全局布尔，五版锁定契约）。
6. 每产生一条消息就持久化（修订 session-turn 落盘时机）；加载会话时修复断尾。

## 后果

- 五版需同步：过渡期 conformance 新场景（SC-005…SC-010）先标 `draft`，
  非 TS 版差异按 `docs/conformance-normalization-policy.md` 登记 ALLOW_DIFF
  并写明到期日，不允许静默跳过。
- `kernel/types.ts` 的事件模型是纯增量：新事件 `context_edit / tool_error / limit`，
  `trimmed / compact` 增加可选 `at`；旧壳忽略未知事件即可，`TurnEndReason`
  不新增取值（到上限仍以 `completed` 结束，由 `limit` 事件表达原因）。
- provider 返回值增加可选 `finishReason`（归一化映射见 specs/provider.md），
  缺省 `unknown`，旧 fake provider 零改动。

## 否决的方案

- 直接依赖 langchain：破坏"核心零依赖手写"与五语言同构两个卖点。
- LangGraph 图运行时 / StateGraph：单循环足够，YAGNI。
- LCEL / callbacks 体系：已有单一 `AgentEvent` 事件出口，更简单。
- modelRetryMiddleware：与"只在首字节前重试"（providers/retry.ts）的长板冲突。
