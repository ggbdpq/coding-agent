# Conformance Design Risks（设计风险登记 v1）

状态：设计冻结（2026-10-01）。一致性体系的特殊之处：**它的失败模式是"安静地变绿"**。
本文登记已知风险、各自的失效信号与结构性对策；runner 实现后每条风险要有对应的
检测手段，没有检测手段的风险条目视为未落地。

## R1 · Normalization 过度 → 假绿（隐藏真实漂移）

- 失效路径：为了让五个实现都能通过，把差异一条条加进允许表；表越长，能看见的漂移越少，
  最终套件只验证"五版都跑了"。
- 信号：E 表只增不减；某场景长期全绿但从未抓到过任何东西。
- 对策：归一化条目必须锚 specs（policy 元原则 2）；diff 报告三元分类 + fail closed；
  **红操演练**：每次升 frozen 前手工注入一次 spec 反例（如改一版锁定文案），
  套件必须转红——红过的套件才可信。

## R2 · Scenario 绑定实现 → 失去语言中立

- 失效路径：场景断言顺手写了某版的输出细节（提示符文案、某版独有的日志行），场景从
  "描述行为"退化成"记录 tcode 长什么样"；第六语言进场即全红。
- 信号：场景源出现实现名/私有路径；新语言接入成本 ≠ 1 个 adapter。
- 对策：R-schema-1 零实现词 grep 门（机器强制）；断言只允许落在四个观测面通道；
  期望值锚 specs 而非任何实现（R-schema-2）。

## R3 · 数量代替覆盖 → Case 很多但价值低

- 失效路径：场景按"容易写"繁殖（十个变体都在测同一条例则），行为面却有大片 spec
  反例清单无场景承接。
- 信号：新增场景说不出"承接了哪条 spec 规则/反例"；两个场景删掉任何一个都不缺证据。
- 对策：R-schema-3 断言必锚规则；维护"spec 规则 → 场景"追溯表；新场景准入问题固定为
  "它让哪条反例清单条目获得了机器执行？"——答不出不收（首批限 5 条即此意）。

## R4 · 观测面演化 → 适配器腐蚀

- 失效路径：exec 输出标记、退出码语义、REPL 命令集是适配器的采集面；某版"顺手"改了
  `[tool]` 行格式，五个适配器之一悄悄失聪，场景开始跳过而非失败。
- 信号：适配器采集到空流却报绿；某版场景从 skip 变成常态。
- 对策：观测面在 ADR-002 已升格为被锁定的公共接口——其变更走 ADR；runner 对
  "空采集/解析失败"报**基建错误**（lessons L2），禁止静默跳过。

## R5 · 剧本保真度 → 测装配不测行为（或反之不确定）

- 失效路径：model_script 过紧（逐步校验 header/字段全量）→ 场景变成协议解析器测试；
  过松（任何回包都行）→ 同一场景两次运行结果不同，比对失效。
- 信号：断言里出现线格式细节（分片方式、SSE 事件边界）；或同一场景五版各有各的"剧本"。
- 对策：剧本 = 逻辑响应步 + 剧本序路由（schema §3.2），协议编码归 adapter；
  分片级考验（provider 主题）明确留在各版自有冒烟，不入一致性场景。

## R6 · 平台差异制造假 diff

- 失效路径：fixture 用绝对路径/平台分隔符/CRLF，或断言含路径字面量——Windows 与 POSIX
  跑出不同结果，被误读为"实现漂移"。
- 信号：同一提交在两平台红绿不同；diff 报告里出现路径大小写/分隔符差异。
- 对策：fixture 相对沙箱 HOME + 内容强制 LF（schema §3.2）；路径类断言用相对路径与
  归一化分隔符；CI 矩阵（ubuntu）反着用——平台性红即暴露 R6 类伪影。

## R7 · 陈旧产物 → 整层证据无效

- 失效路径：即 lessons L1（rcode 冒烟 7/7 假红案例）：缓存里编译期烧死的旧二进制路径
  让可执行层全红，或更危险的——旧二进制让可执行层"安静地绿在旧行为上"。
- 信号：spawn 类基建错误；或 adapter 跑的产物时间戳早于源码最后变更。
- 对策：适配器强制通过**构建新鲜度门**（重建或校验产物新鲜度）；门失败 = 基建错误，
  不产生任何行为判定（policy §5）。
