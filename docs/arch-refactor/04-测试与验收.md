## 3. 新增一致性场景（WP7 编写，初始 `maturity: "draft"`）

需要先把 `conformance/adapters/shared.mjs` 的假 provider 从 `tool-then-text` 扩展为**按请求序号回放的剧本**：

```js
model_script: {
  kind: "steps",
  steps: [
    // 每个元素对应第 N 次请求
    { tool_call: { name: "write", raw_arguments: "{\"path\":\"a.ts\",\"content\":\"export" }, finish_reason: "length" },
    { text: "已停止写入，参数被截断。" },
  ],
}
```

- `raw_arguments`：原样发送字符串（用来造非法 JSON）；`arguments`：对象，`JSON.stringify` 后发送（兼容旧剧本）。
- `finish_reason`：覆盖缺省值。
- sink 额外记录每个请求体的字符数，供"请求不超限"断言。
- `tool-then-text` 旧剧本保持可用，SC-001/002 不改。

| 场景 | 标题 | 剧本要点 | 期望（只锚 spec，不抄实现） |
|---|---|---|---|
| SC-005 | 轮内上下文治理 | fixture 放一个 60KB 文件；8 次 `read` 再给文本；`contextLimit` 配小 | 每个 provider 请求体估算 ≤ 上限；stdout 出现治理标记 |
| SC-006 | 非法工具参数 | `raw_arguments` 为非法 JSON | 工具不执行（fixture 文件不变）；第 2 次请求里 tool 消息含固定话术 |
| SC-007 | 截断参数 | `finish_reason:"length"` + 截断参数 | 同 SC-006，分类为截断 |
| SC-008 | 授权粒度 | repl-script：对 write 回答 `s`，再来一次 bash | bash 仍出现审批提示；另一臂回答 `a` 时 bash 不再询问（锁住 R3 不变） |
| SC-009 | 轮次上限 | `maxToolRounds:2`，剧本一直给工具调用 | 出现 limit 标记；最后一次请求不带 tools |
| SC-010 | 崩溃恢复 | 工具执行中杀进程，再 `--resume` | 重启后第一次请求消息序列合法（没有悬空 tool_calls） |

非 TS 版本：在 `docs/conformance-normalization-policy.md` 增加 E 条目，标注"TS 先行、其他版本待同步"，判定为 ALLOW_DIFF，并写明到期日。不允许静默跳过。
