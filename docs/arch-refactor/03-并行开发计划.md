## 3. 分支与合并顺序

| 工作包 | 分支名 | 合并顺序 |
|---|---|---|
| WP0 | `feat/wp0-contracts` | 1 |
| WP7 | `feat/wp7-conformance` | 2（越早越好，其他包能用它的场景做红测） |
| WP3 | `feat/wp3-toolargs` | 3 |
| WP4 | `feat/wp4-permission-scope` | 3 |
| WP6 | `feat/wp6-incremental-persist` | 3 |
| WP1 | `feat/wp1-middleware` | 4（最后合并第一批，因为它改 agentloop 骨架最多） |
| WP2 | `feat/wp2-midturn-governance` | 5 |
| WP5 | `feat/wp5-limits` | 5 |

规则：

1. 每个分支都从**最新的 develop** 拉，合并前 `git rebase develop`。
2. 合并门：`npm test` 全绿 + `npm run check` 通过 + `node conformance/run.mjs` 中自己相关的场景按 04 预期变色。
3. 一个 PR 只做一个工作包；发现需要改接口，先回 WP0 补一个小 PR，不要在自己分支里改 `kernel/types.ts`。

## 4. 冲突热点与化解

| 热点 | 为什么会冲突 | 化解 |
|---|---|---|
| `core/agentloop.ts` | WP1 重排循环，WP3、WP5 各改一处 | WP3/WP5 先合并，只改单行；WP1 rebase 时把这两行搬进新骨架。WP1 提示词里已写明保留它们 |
| `core/turn.ts` | WP6 改落盘，WP1 接线，WP2 删轮前治理 | WP6 先合并；WP1 只加参数；WP2 在第二批才动 |
| `shell/web.html` | 多包各加一个 `case` | 每个 `case` 独立成块、按事件名字母序插入，冲突时两边都保留 |
| `specs/agent-loop.md` | WP1/WP3/WP5 各改一条规则 | 每个包只改自己那条 R 编号的段落 |

## 5. 给并行代理的统一硬约束

写进每份 Cursor 提示词，这里集中列一次：

- 核心零依赖：不新增任何 npm 依赖，不引入 langchain；只借语义。
- 不改已有事件、消息、工具的字段名和 id；只做增量。
- `core/` 不得 import 网络模块（ARCHITECTURE 规则）。
- agent loop 本身不插件化（Q4 决策）：中间件是 loop 内部的组合点，不是插件注册表。
- 先写失败的测试，再改实现；`npm test` 全绿才算完成。
- 改行为必须同步改 `specs/` 对应规则，并在 PR 里列出 spec diff。
- 只改 TypeScript 版；其他四种语言在 `docs/` 里登记待同步，不在本轮改。
