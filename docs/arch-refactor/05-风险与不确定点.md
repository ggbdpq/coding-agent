# 05 · 风险与不确定点

| # | 风险 / 不确定点 | 影响 | 处理建议 | 归属 |
|---|---|---|---|---|
| R1 | **轮内压缩增加延迟和费用**：每次模型调用前都可能触发一次摘要调用 | 长任务变慢、多花 token | 先做零成本的"清理旧工具输出"，只有仍超 80% 才压缩；同一轮最多压缩 2 次，超过就退到裁剪 | WP2 |
| R2 | **token 估算偏粗**：`core/trim.ts:12` 的 `estimateTokens` 是字符估算（每条消息 +8 字符，总数 `ceil(chars/3)`），中文和代码误差方向不同 | 阈值可能早触发或晚触发 | 不在本轮换分词器；provider 返回的 `usage.prompt_tokens` 存在时，用它校准下一次估算（可选，WP2 加 TODO） | WP2 |
| R3 | **bash 授权键可被绕过**：按命令首词授权时，`bash -c "…"`、`sh`、`env`、`xargs`、管道、`;`、`&&`、命令替换都能夹带别的命令 | "本会话允许 npm" 变成后门 | 首词属于 `bash/sh/zsh/env/xargs/sudo/eval/exec` 或命令里出现 `; && \|\| \| $( \``、重定向 `>` 时，**不提供 scoped**：只显示"允许一次 / 拒绝 / 本会话全部允许" | WP4 |
| R4 | **anthropic stop_reason 映射**：`end_turn`/`stop_sequence`→stop，`tool_use`→tool_calls，`max_tokens`→length，`refusal`→content_filter；新增值落 `unknown` | 映射漏掉会误判截断 | 映射表写进 `specs/provider.md`；未知值不报错，只是不触发截断识别 | WP3 |
| R5 | **截断但 JSON 碰巧合法**：length 截断时参数可能恰好闭合 | 写入半截内容 | `finishReason === 'length'` 时即使 JSON 合法也视为 `truncated_args`，不执行 | WP3 |
| R6 | **增量落盘写放大**：每条消息一次 append | 大工具输出频繁写盘 | 仍用 append-only JSONL；单条写失败只告警不中断；不做 fsync | WP6 |
| R7 | **旧会话文件兼容**：历史文件里可能有断尾 tool_calls | 加载后第一次请求被 provider 拒绝 | 加载时调用与 `turn.ts:73-85` 同一个修复函数补占位 tool 消息 | WP6 |
| R8 | **压缩后 checkpoint 语义**：压缩改写了历史，append-only 文件不能"改"前文 | 重启后历史不一致 | 沿用已有机制：`core/session.ts:93` 的 `checkpoint()` 写 `{type:'context_checkpoint', messages}`，加载时（`session.ts:118`）以最后一个 checkpoint 为起点。轮内压缩同样调用它 | WP2（调用）+ WP6（保证加载后再修断尾） |
| R9 | **modelRetry 重复输出**：langchain 的 modelRetry 在流式中途失败后重试，可能重复已输出的 token（**推断**，未在 langchain 源码里验证到去重逻辑） | 若照搬会让 UI 文字重复 | 保持现状：只在收到首字节前重试（`providers/retry.ts`），不借这个 | — |
| R10 | **Tauri/WebKit 渲染差异**：新增事件行在 WebKit 下样式可能不同 | 桌面端显示异常 | 新增 `case` 只用已有的 CSS 类，不新加布局 | WP2/WP3/WP5 |
| R11 | **五语言漂移**：只改 TS 版，其余四版行为会落后 | 一致性场景对其他语言失败 | 新场景先标 `maturity: "draft"`，非 TS 的差异按 normalization-policy 新增 E 条目记为 ALLOW_DIFF，并登记同步排期 | WP7 |
| R12 | **中间件顺序错误导致越权**：用户中间件放在权限闸门内侧就能绕过审批 | 安全问题 | `permission` 固定为最内层，组合器在注册时断言；有单测 | WP1 |
| R13 | **轮内改写后 `mark` 失效**：`turn.ts:24` 的 `appendSince` 用 `app.messages.slice(mark)` 落盘；轮内压缩/裁剪会让下标错位，导致漏写或重写 | 会话文件重复或丢消息 | WP6 改为逐条 `onMessage` 落盘后，`appendSince` 删除；`replaceMessages` 必须同时重算 `mark`（不变式 I3），有单测 | WP1 + WP6 |
| R14 | **权限是五版锁定契约**：`specs/permission.md` R2/R3 及偏离清单明确"always = 进程内全局布尔，不按工具分粒度" | 直接改 always 语义会让五版同时漂移、破坏已冻结的测试 | WP4 不改 always，只新增第四态 scoped；仍需 owner 拍板是否接受新增审批选项 | WP4 |

- 行号基于 `bbac303`，rebase 后可能偏移；提示词里都要求先 `rg` 定位。
